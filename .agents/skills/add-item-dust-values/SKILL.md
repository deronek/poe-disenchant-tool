# Add item dust values

Use when a newly released unique needs to appear in the disenchant table, or an existing item's dust value is wrong.

The app stores two files:

- `data/dust/poe-dust-original.js` is the source. You edit this by hand.
- `data/dust/poe-dust.js` is generated by `scripts/process-dust-data.ts`. Never edit it by hand.

Both files hold thousands of entries and are large. Never read or `cat` them in full. Use `grep`, `sed`, or `tail` to inspect only the entry you need.

Never guess. Every field must come from poedb or an existing dataset row. If the item or a field is missing, stop and tell the user what could not be found.

## 1. Confirm the item is missing

```sh
grep -n "Item Name" data/dust/poe-dust-original.js src/lib/item-data/ignore-list.ts
```

If the item is in the ignore list, stop and do not add it.

## 2. Get the base dust value from poedb

Open `https://poedb.tw/us/Kingsmarch` and find the item in the Disenchant table. The row looks like this:

```html
<a href="Bane_of_the_Apostate">Bane of the Apostate</a></td>
<td>9.06</td>
<td>18120</td>
<td>21744</td>
```

Use the first numeric column (`9.06`) as `dustVal`. This is what the dataset stores for every existing item.

Do not use the two columns after it. Poedb calculates those at its own item level. The app calculates ilvl 84 values from `dustVal` in `src/lib/dust/calculation.ts`, and its result is 25% higher than poedb's ilvl 84 column for every item in the dataset. That difference is expected.

A quick extraction for one item:

```sh
curl -sSL --compressed https://poedb.tw/us/Kingsmarch |
  grep -o 'Bane_of_the_Apostate">Bane of the Apostate</a></td><td>[0-9.]*'
```

If poedb does not list the item yet, do not invent a value. Stop and tell the user it is not available.

## 3. Get the metadata from the item page

Open `https://poedb.tw/us/<Item_Slug>`, for example `https://poedb.tw/us/Bane_of_the_Apostate`.

- `name` is the exact item name.
- `baseType` is the BaseType field on the page, such as `Judgement Staff`.
- `link` is the poedb URL.
- `w`, `h`, and `slots` come from the item's inventory size. Reuse an existing row with the same base type. `slots` must always equal `w * h`.

Typical sizes:

| Item type      | Size |
| -------------- | ---- |
| Ring, amulet   | 1x1  |
| Helmet, shield | 2x2  |
| Body armour    | 2x3  |
| Staff, bow     | 2x4  |

## 4. Add the entry

Append the object to the array in `data/dust/poe-dust-original.js`. The file is not alphabetical, so appending keeps the diff small.

```js
  {
    name: "Bane of the Apostate",
    baseType: "Judgement Staff",
    dustVal: 9.06,
    w: 2,
    h: 4,
    slots: 8,
    link: "https://poedb.tw/us/Bane_of_the_Apostate",
  },
```

The processing script rejects duplicate names and entries where `w * h !== slots`.

## 5. Regenerate the app data

```sh
pnpm dust:process
```

This runs `scripts/process-dust-data.ts` and then `scripts/validate-dust-data.ts`. It writes `data/dust/poe-dust.js`, which must be committed together with the source file.

## 6. Check the generated values

At ilvl 84 and quality 0 the current formula is `dustVal * 2500`. At quality 20 it is `dustVal * 3500`. Gold cost comes from `src/lib/gold/calculation.ts`.

For example, `9.06` becomes `22650` and `31710` with `5400` gold. If the generated numbers do not match those ratios, the input is probably wrong.

## 7. Check the result

The processing run already validates the source and writes the generated file. Confirm the new entry appeared with the right values:

```sh
grep -n -A5 'name: "Bane of the Apostate"' data/dust/poe-dust.js
```

`pnpm lint` is enough for repository checks. Unit tests and a production build do not prove a data addition: the build only validates the dataset shape, and the app only shows an item once a market price is available for it. A missing price means the item is absent from the UI, not that the dust data is wrong.
